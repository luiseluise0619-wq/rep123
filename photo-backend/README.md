# 직원별 방문 사진 · MYBOX v3

기존 Vercel 지도에서 주소의 **현장 촬영 · 사진 2장**을 누릅니다. 사진 화면 안에서도
시도 → 구군 → 행정 읍면동 → 원주소를 선택할 수 있습니다. 사진 바이너리와 비공개 집계
JSON은 MYBOX에 보관하고 Apps Script는 인증·API 중계·잠금만 담당합니다.
Google Drive/Sheets/Forms에 사진을 저장하지 않습니다. 원주소·좌표·사업자 집계는 변경하지 않습니다.

## 권한과 직원 링크

- 관리자는 `admin`과 별도 관리자 암호로 `/exec?page=admin`에 접속합니다.
- 관리자가 직원 이름·아이디를 등록하면 직원 전용 링크가 **한 번만** 표시됩니다.
  직원 최대 100명. 같은 이름도 서로 다른 불변 계정 ID로 구분합니다.
- 전용 링크는 암호와 같은 접속키입니다. 해당 직원에게만 전달하고 공개방·GitHub에 올리지 않습니다.
  링크를 가진 사람이 해당 직원으로 접속하므로 공식 본인 인증은 아닙니다.
- 직원은 비밀번호 입력 없이 링크의 시작 버튼을 누릅니다. 서버가 계정별 소유권을 검사하여
  **본인 계정으로 올린 사진만** 조회합니다. 주소 전체의 점유 수량은 보이지만 남의 사진·작성자 정보는 숨깁니다.
- 관리자는 모든 사진·주소별 사진 수·전체 갤러리·CSV·직원 링크 발급/재발급/중지를 사용합니다.
- 재발급/중지하면 이전 링크와 기존 로그인 세션은 즉시 무효입니다. 재허용 시 기존 링크는 다시 사용 가능하지만
  과거 세션은 살아나지 않습니다. 계정 ID는 재사용하지 않아 재발급해도 기존 사진 소유권은 유지됩니다.
- v2 공용 암호·자기 신고 이름으로 저장한 과거 사진은 작성자를 증명할 수 없어 **관리자만** 봅니다.
  과거 공용 로그인 세션도 v3에서 거절합니다.
- URL의 접속키는 `#` 뒤에 두고 성공 로그인 후 제거합니다. 기기에는 접속키/암호 대신 8시간 서명 세션만 저장합니다.
  기본은 현재 탭이며 개인 기기에서만 8시간 유지를 선택합니다. 브라우저 저장 차단 시 메모리로 동작합니다.

## 비밀값 설정 — 소유자만 직접 입력

Apps Script **프로젝트 설정 → 스크립트 속성**:

- `MYBOX_TOKEN`: 기존 MYBOX 개인 액세스 토큰 유지.
- `PHOTO_ADMIN_PASSWORD`: 8~200자, 기존 팀 공용 암호와 **다른** 관리자 암호. 권장 12자 이상 무작위 값.
- 기존 `PHOTO_TEAM_PASSWORD`는 v3 로그인에 사용하지 않습니다. 관리자 암호와 같으면 서비스가 중단됩니다.

`PHOTO_AUTH_KEY_V3`, `PHOTO_EMP_*`, 집계 대기/스캔 속성은 서버가 관리합니다. 임의 수정하지 않습니다.
직원 키는 원문 대신 서버 키 기반 HMAC으로 저장합니다. 비밀값·세션·직원 링크를 채팅/소스/로그에 출력하지 않습니다.
PAT 교체는 직원 계정을 바꾸지 않습니다. 관리자 암호 변경은 기존 관리자 세션을 무효화합니다.
PAT는 일반 계정 파일 전체 권한이므로 전용 계정이 권장됩니다. 앱 폴더 제한은 서버 코드의 제한이며 PAT 자체의 제한이 아닙니다.
프로젝트 편집자는 비밀값에 접근할 수 있으므로 직원에게 편집 권한을 주지 않습니다.

## 설치/기존 배포 갱신

1. `node scripts/bundle-photo-backend.cjs`로 로컬 `../work/mybox-photo-bundle.gs` 생성.
2. 생성된 내용 전체를 기존 Apps Script `Code.gs`에 넣고 저장합니다.
   원본은 `Code.gs` + `Access.gs` + `Catalog.gs` + 두 HTML입니다. 번들만 붙이면 별도 HTML 파일은 불필요합니다.
3. 소유자가 위 관리자 암호 속성을 직접 저장합니다. 비밀값을 소스에 넣지 않습니다.
4. 기존 웹 앱의 **배포 관리 → 수정 → 새 버전**으로 갱신합니다. 실행 사용자=소유자,
   기존 모든 사용자 공개 HTML을 유지하되 사진/API는 서버 인증으로 보호합니다.
   최종 배포·Google 권한 승인은 소유자가 확인합니다. Gmail/Drive/연락처 권한은 사용하지 않습니다.
5. 동일 `/exec` URL을 유지합니다. URL이 바뀌면 `Code.gs`와 `web/photo-config.js`를 함께 변경합니다.
6. 관리자 로그인 후 기존 사진 가져오기/동기화를 완료합니다. 직원 링크는 관리자 화면에서 소유자가 직접 발급합니다.
7. 실제 계정 로그인·조회·정상 현장 사진 업로드·재조회 전에는 실사용 완료로 표시하지 않습니다.

## 관리자 집계의 정확성과 복구

사진 원본 `현장방문_주소사진_v1`과 별도 비공개 `현장방문_사진목록_v3`에 16개 분할 JSON+manifest를 저장합니다.
집계는 인증 근거가 아니며 사진 조회/저장 때 서버가 원본 파일을 다시 검사합니다. 목록의 1건은 **원주소 1곳**이고 사업자 수가 아닙니다.

저장 확인 후 집계가 실패하면 사진 저장 성공을 유지하고 대기 주소를 표시합니다. 관리자 동기화는 대기 주소를 복구합니다.
기존 사진은 회당 4개 주소 폴더씩 이어 읽고 완료 전 **부분 집계**를 명시합니다. 전체 재대조는 오래된 집계만 정리하며 사진 원본을 삭제하지 않습니다.
알 수 없는 수동 폴더/주소는 확인 필요로 남깁니다. MYBOX를 직접 변경했다면 전체 재대조를 실행해야 합니다.
미등록 주소는 목록에 표시하지 않습니다. 갤러리는 24장씩, 사진 보기를 눌렀을 때만 이미지를 조회합니다.
CSV는 현재 불러온/검색된 목록이며 부분 목록 여부를 화면에서 확인합니다.

## 촬영·압축·무료 안전 한도

- 원주소 42,401곳 × 최대 2장 × 200,000 bytes = 최대 16,960,400,000 bytes(약 17GB), 별도 집계 메타데이터 추가.
  동일 주소에 사업자가 여러 개여도 해당 주소 전체 2장입니다.
- 모바일 카메라 버튼은 후면 카메라를 요청합니다. 실제 동작은 휴대폰/브라우저에 따라 파일 선택으로 보일 수 있습니다.
  PC에서 실물 휴대폰 카메라까지 검증한 것으로 취급하지 않습니다.
- 원본을 자르지 않고 하단 여백에 **앱 기록(KST·기기 시각), 방문일(직접 입력), 선택 원주소**를 넣습니다.
  최종 긴 변 1600px, 장당 200KB 이하 JPEG. 해상도가 너무 낮거나 압축 후 날짜가 안 읽히면 거절/재촬영합니다.
- EXIF 날짜/GPS는 제거됩니다. 기기 시계와 선택 주소는 조작 가능하며 GPS 방문 인증·촬영 진위 증거가 아닙니다.
  서버 저장 시각은 별도 표시합니다. 지도 좌표도 참고값이며 정확성을 새로 보증하지 않습니다.
- 서버는 원주소 allowlist·JPEG 실제 바이트/해상도·확인 체크·방문일·2장 제한·소유권을 재검증합니다.
  사진 해시로 재시도 중복 방지, 원본 삭제/덮어쓰기 기능 없음. 집계 JSON만 전용 경로에서 덮어씁니다.
- 계정 전체 사용량 **min(24GB, 할당량−1GB)**에서 저장 중단. 사진 외 기존 개인 파일도 사용량에 포함됩니다.
- 하루 저장 시도 1,000회·사진 조회 2,000회·전체 외부 요청 10,000회 안전 상한. 집계 동기화도 요청을 사용합니다.
  실제 Google/MYBOX 한도가 먼저 도달할 수 있습니다. 카드 등록·유료 업그레이드·자동 결제 경로는 만들지 않습니다.
- 모든 RPC를 프로젝트 전역 잠금으로 한 번에 하나씩 처리합니다. BUSY만 1.5·3·5·8초(+0~0.5초) 제한 재시도합니다.
  인증/용량/모호한 네트워크 실패는 자동 반복하지 않습니다.
- 로그인 ID별 실패 제한과 전역 20회/10분 제한을 둡니다. 공격자가 신규 로그인을 일시 차단할 수 있어 무중단 서비스를 보장하지 않습니다.
- 동시 직원 수는 부하 테스트 전 보장하지 않습니다. 소규모 실제 운영부터 확인합니다.
  하루 1,000회는 2장씩 산술 최대 500곳분일 뿐, 실제 처리 보장치가 아닙니다.
