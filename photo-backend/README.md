# 현장 촬영·사진 관리 · MYBOX v8 (GPS 사용 안 함)

현재 운영 설정은 `requireCapture: true`, `requireLocation: false`입니다.

- 관리자 화면도 흰색·회색·파란색으로 통일했습니다. 주소·사진 두 가지 합계, 검색, 주소별/사진 보기 중심이며 저장소 정보·상세 시각·진단은 접어서 표시합니다. 미완료 집계 경고와 삭제 확인은 유지합니다.
- 사진·관리자 화면에 초기 ‘여는 중’ 표시와 연결 단계 안내, 실패 시 다시 열기/불러오기 버튼이 있습니다. 사진 화면은 지도용 `addresses.js` 약 4.8MB를 내려받지 않고, 서버가 원주소를 확인한 후에만 촬영을 켭니다.
- 서버는 한 요청 안에서 원주소 인덱스를 한 번만 만들고, 관리자 권한 확인은 불필요한 MYBOX 공간 조회를 생략합니다. 주소 검증·세션·무료 안전 한도·GPS 미수집 조건을 완화하지 않습니다. Google 초기 연결 지연 자체가 없어지는 것은 아닙니다.
- `tests/photo-all-addresses.test.cjs`: 원주소 42,401개 링크·서버 분류 검사 및 17개 시도×2장 모의 저장 검사입니다. 실제 42,401개 주소에 사진을 등록한 실사용 시험이 아니며 네트워크·브라우저·2장 제한·무료 한도는 별도입니다.

- 촬영 화면은 카메라만 요청합니다. 위치 권한 요청, 좌표, GPS 정확도, 거리 표시와 전송은 제거했습니다. `/photo`의 Permissions-Policy도 geolocation을 차단합니다.
- 한 장 촬영 후 카메라 종료 → ‘확인하고 한 장 더 찍기’ → 두 번째 촬영 후 카메라 종료 → 공개 동의 후 ‘확인하고 전송’ 순서입니다. 첫 확인은 자동으로 다음 카메라를 열며 업로드하지 않습니다. 주소당 최대 2장이며 보조 버튼으로 한 장만 확인·전송할 수도 있습니다. 별도의 ‘확인’ 버튼은 없으며 재촬영은 앞서 확인한 사진을 유지합니다.
- 촬영 화면은 흰색·회색 바탕과 파란색 주요 버튼으로 구성합니다. 첫 사진의 공개 동의·전송은 ‘한 장만 전송하기’를 눌러 펼치고, 두 번째 사진에서는 바로 표시합니다. 촬영·재촬영 시 공개 동의를 초기화하며, 일부 전송 실패 시 남은 사진과 재시도 버튼을 유지합니다.
- 서버는 주소·브라우저에 묶인 서명 촬영 허가와 시각을 검사합니다. 새 촬영 기록에는 `locationCollected: false`, 촬영·수신 시각만 보관하고 위치는 저장하지 않습니다.
- 전환 전에 발급한 유효한 촬영 허가는 업로드할 수 있지만 새로 저장할 때는 포함된 GPS를 버립니다. 이전에 저장한 사진·위치 기록을 삭제하거나 덮어쓰지는 않습니다.
- 관리자 화면·CSV는 주소, 사진 수, 촬영·등록 시각을 표시합니다. GPS 관련 표시/열은 제거했으며 기존 기록은 서버에 보존합니다.
- 기존 200KB 압축, 주소당 2장 제한, 공개 조회, 올린 브라우저·관리자만 삭제, 응답 제한시간·중복 방지, MYBOX 동기화는 유지합니다. GPS가 없어도 실제 방문 보증이나 완전한 카메라 위변조 방지 기능은 아닙니다.

## 이전 v5/v6 설계 기록 (GPS 기능 중단 전 참고)

아래의 위치·거리 설명은 과거 동작입니다. v7에서는 위의 GPS 없는 흐름이 적용됩니다.

현재 등록 진입점은 지도 사이트의 `/photo?address=...`입니다. 앨범/파일 선택 없이 `getUserMedia` 카메라 화면에서만 촬영합니다.
구글 HTML iframe에서 카메라·위치를 요청하지 않으며, 같은 Vercel 사이트에서 사용자가 안내에 동의한 뒤 권한을 허용합니다.

- `web/photo.html` + `field-photo.js`: 현재 위치 수신 → 서명 촬영 허가 → 카메라 프레임 → 날짜/방문 주소 표시 → 200KB 이하 압축 → 공개 동의 후 등록.
- 한 장을 촬영하면 카메라 트랙을 종료하고 사진 확인 화면으로 전환합니다. 사진별 ‘확인’ 후 ‘한 장 더 찍기’ 또는 전송을 선택합니다. 확인하지 않은 사진은 전송하거나 다음 촬영으로 건너뛸 수 없으며, 재촬영 시 앞서 확인한 다른 사진은 유지합니다. ‘확인’ 자체는 업로드가 아닙니다. 기존처럼 주소당 최대 2장이고, 1장만 확인 후 전송하는 것도 허용합니다.
- `Bridge.html`: 허용된 사이트·무작위 채널·메시지 출처를 검증하는 공개 RPC 중계. 관리자 API는 중계하지 않습니다.
- 구글과 네이버 인증 토큰은 서버에만 있습니다. 기존 브라우저 삭제키는 허용 사이트의 전용 채널을 통해 이관하며 URL/로그에 넣지 않습니다.
- `Capture.gs`: 위치 형식·수신 시각·촬영 허가 서명/기한·브라우저/방문 주소 일치를 검사합니다. 기기가 보고한 GPS이며 실제 방문이나 조작 방지를 보증하지 않습니다.
- 좌표/정확도/촬영·수신 시각은 MYBOX 비공개 `evidence-*.json`에 먼저 보관합니다. 공개 JPEG/조회 응답에는 GPS를 넣지 않습니다.
- 관리자 목록/사진 보기/CSV에서 방문 주소, 서버 등록 시각, 기기 보고 좌표·정확도·수신 시각을 확인합니다. 기존 사진의 없는 GPS는 만들지 않습니다.
- 촬영 화면·사진 미리보기·관리자 목록/CSV에서 현재 GPS와 선택한 방문지 지도 좌표 사이의 직선거리를 계산합니다. `web/lib/visit-distance.js`의 동일 Haversine 계산을 화면과 서버 번들에서 사용하며, GPS 추정 정확도(예: ±24m)와 방문지 거리를 별도 표시합니다. 길찾기 거리가 아니고, 방문지 좌표 미확정이면 참고용으로 표시합니다. 등록 거리도 서버가 서명한 좌표에서 다시 계산하고 공개 조회에는 내보내지 않습니다. 거리로 등록을 차단하거나 현재 위치를 다른 주소에 자동 배정하지 않습니다.
- 관리자 ‘새로고침’ 한 번으로 MYBOX 사진 전체 대조(진행 중인 확인은 이어서) → 집계 갱신 → 주소 목록 표시를 실행합니다. 별도 동기화/재대조/목록 갱신 버튼은 없습니다. 일시정지·오류는 완료로 표시하지 않으며, 목록 읽기 실패 시 마지막 목록을 유지합니다. 각 관리자 RPC 대기는 90초로 제한하고 불명확한 요청은 자동 재전송하지 않습니다.
- 등록 RPC 응답 대기는 90초로 제한하고 상태 조회는 30초로 제한합니다. 불명확한 저장은 자동 재전송하지 않으며, 재시도 전에 같은 브라우저·사진 해시의 저장 여부부터 확인합니다.
- `diagnosePhotoStorage`: 관리자 전용. 별도 `연결점검_현장방문아님`에 표시된 합성 JPEG 한 장을 저장·다운로드 대조한 뒤 해당 사진만 휴지통으로 이동합니다. 방문 집계와 분리합니다. 실제 실행은 소유자의 동의 후 진행합니다.
- 합성 테스트 자산 재생성: `python scripts/create-mybox-diagnostic.py` (Pillow). 번들: `node scripts/bundle-photo-backend.cjs`.
- 신규 검증: `node --test tests/photo-capture.test.cjs tests/field-photo-ui.test.cjs`. 기존 테스트는 v3/v4 이관과 소유권 회귀도 별도로 검사합니다.

## 이전 v4 설계 기록 (기존 사진·삭제키 호환 참고)

아래의 앨범 선택/구글 촬영 화면은 과거 구현입니다. v5 신규 등록은 위의 카메라·위치 흐름만 허용합니다.

현재 요구사항은 **누구나 로그인 없이 등록·보기, 삭제는 올린 브라우저 또는 관리자만**입니다.
기존 v3 직원별 비공개 방식과 다릅니다. v4 공개 배포 전 소유자가 기존 저장 사진까지 공개됨을 확인해야 합니다.
사진에 얼굴·연락처 등 개인정보가 없고 공개할 권한이 있는지 확인합니다.

## 사용 방법

- 기존 Vercel 주소 지도 → 주소의 **현장 촬영 · 사진 2장** → 촬영 또는 파일 선택 → 공개 안내 확인 → 저장.
- 사진 페이지 안에서도 시도 → 구군 → 행정 읍면동 → 원주소를 선택할 수 있습니다.
- 주소 전체 최대 2장입니다. 같은 주소의 사업자가 여러 명이어도 사진 한도는 2장입니다.
- 모든 방문자는 기존 저장 사진과 새 사진을 열람할 수 있습니다. 공개 응답에는 계정 이름·파일명·MYBOX ID·소유권 해시를 넣지 않습니다.
- 올린 브라우저에는 ‘내가 올린 사진 삭제’와 ‘삭제 확인/취소’가 표시됩니다. 다른 브라우저에는 삭제 버튼이 없습니다.
- 관리자는 `/exec?page=admin&build=2026-10-16-mybox-v4-public`에서 별도 암호로 로그인합니다.
  주소별 수량·전체 갤러리·CSV·사진 삭제를 사용합니다. 사진을 열고 ‘휴지통으로 이동 → 관리자 삭제 확인’을 누릅니다.
- 공개 등록에는 직원 전용 링크가 필요 없습니다. 과거 계정 기능은 호환용으로 남지만 새 공개 화면에서는 사용하지 않습니다.

## 삭제 권한과 한계

브라우저가 Web Crypto로 만든 256비트 무작위 삭제키를 `photoDeviceKeyV4` 로컬 저장소에 보관합니다.
서버는 키의 SHA-256 기반 식별자만 사진 파일명에 저장하고, 매번 실제 주소 폴더·파일 소유권을 확인합니다.
원문 키는 MYBOX 파일·공개 응답·로그·GitHub·URL에 저장하지 않습니다.

- ‘올린 사람’이 아니라 **비밀키가 남아 있는 동일 브라우저**의 권한입니다. 공식 본인 인증이 아닙니다.
- 다른 기기/브라우저, 시크릿 모드 종료, 브라우저 데이터 삭제 후에는 관리자에게 삭제를 요청해야 합니다.
- 공용 기기에서는 그 기기를 사용하는 다른 사람도 삭제할 수 있습니다. 개인 기기를 권장합니다.
- 저장소/암호학 난수 기능이 차단된 브라우저에서는 공개 조회만 가능하며 업로드를 차단합니다.
- v3 계정으로 저장한 과거 사진은 삭제키가 없으므로 관리자만 삭제할 수 있습니다. 공개 조회는 가능합니다.
- 공개 API가 받은 임의 MYBOX ID·폴더·JSON 파일을 삭제할 수 없습니다. 원자료 주소 안의 검증된 JPEG만 대상으로 합니다.
- 사진 ID는 파일 리소스 ID와 이름에서 파생합니다. 삭제 후 같은 칸에 새 사진이 올라와도 오래된 요청으로 새 사진을 삭제하지 않습니다.
- 삭제는 **MYBOX 휴지통 이동**이며 영구 삭제/휴지통 비우기 API는 구현하지 않습니다.
  복원은 소유자가 MYBOX에서 직접 처리하고 관리자 전체 재대조를 실행합니다. 휴지통 파일 때문에 용량이 즉시 줄지 않을 수 있습니다.
- 네트워크가 끊기면 새로고침으로 실제 상태를 확인합니다. 모호한 삭제 요청을 자동 반복하지 않습니다.

## 비밀값 — 소유자가 직접 입력

Apps Script 프로젝트 설정 → 스크립트 속성:

- `MYBOX_TOKEN`: 기존 MYBOX 개인 액세스 토큰 유지.
- `PHOTO_ADMIN_PASSWORD`: 8~200자, 기존 팀 공용 암호와 다른 관리자 전용 암호. 권장 12자 이상 무작위 값.
- 이전 `PHOTO_TEAM_PASSWORD`는 로그인에 쓰지 않습니다. 관리자 암호와 같으면 설정 오류로 중단합니다.

관리자 암호·PAT·직원 키·세션은 채팅/소스/GitHub에 넣지 않습니다. `PHOTO_AUTH_KEY_V3`와 집계/계정 속성은 서버 관리용입니다.
관리자만 서명 세션으로 관리 화면을 사용하며 기본은 현재 탭, 개인 기기에서 선택적으로 8시간 유지합니다.
PAT는 계정의 일반 파일 전체 권한입니다. 앱 폴더 제한은 서버 코드의 제한이지 PAT 자체의 제한이 아닙니다.
전용 계정을 권장하며 직원에게 Apps Script 편집 권한을 주지 않습니다.

## 설치와 배포

1. `node scripts/bundle-photo-backend.cjs` → 로컬 `../work/mybox-photo-bundle.gs` 생성.
2. 빌더가 합친 `Code.gs + Access.gs + Catalog.gs + Public.gs + Capture.gs + Diagnostics.gs` 및 HTML 번들 전체를 기존 Apps Script `Code.gs`에 넣고 저장합니다.
3. 기존 웹 앱의 배포 관리 → 수정 → 새 버전. 실행 사용자=소유자, 기존 공개 HTML 범위 유지.
4. **사진 조회가 비공개에서 공개로 바뀌므로 최종 배포 직전에 소유자 확인이 필수**입니다. 기존 사진도 공개됩니다.
   추가 Google 권한 승인은 소유자가 직접 합니다. Gmail/Drive/연락처 권한은 필요하지 않습니다.
5. 기존 `/exec` 주소를 유지합니다. 주소가 바뀌면 `Code.gs`와 `web/photo-config.js`를 함께 수정합니다.
   새 링크에는 `build` 버전을 붙여 과거 로그인 화면 캐시를 피합니다. 비밀키는 URL에 넣지 않습니다.
6. 실제 관리자 로그인, 정상 현장 사진 업로드·재조회·본인/관리자 휴지통 이동 전에는 실사용 검증 완료로 표시하지 않습니다.

## 압축·타임스탬프

원본을 자르지 않고 하단 띠에 앱 기록(KST·기기 시각), 방문일(직접 입력), 선택 원주소를 넣습니다.
최종 긴 변 1600px·장당 200,000 bytes 이하 JPEG. 원본은 기기에 남기고 날짜 가독성을 확인합니다.
너무 작은/큰 원본·안전하게 압축할 수 없는 사진은 거절합니다. EXIF 날짜/GPS는 제거됩니다.
입력 날짜·기기 시계·선택 주소는 조작 가능하며 실제 촬영/GPS 방문 인증을 보증하지 않습니다.
서버 저장 시각은 별도 표시합니다. 휴대폰 카메라 동작은 기기/브라우저에 따라 파일 선택으로 나타날 수 있습니다.
실물 휴대폰 카메라 및 실계정 바이너리 저장은 모의 테스트와 별개입니다.

## 집계와 무료 운영

사진은 MYBOX `현장방문_주소사진_v1`, 관리자 비공개 집계 JSON은 `현장방문_사진목록_v3`에 저장합니다.
Google Drive/Sheets/Forms에 사진을 저장하지 않습니다. 원주소·지도 좌표·사업자 수는 이 변경으로 수정하지 않습니다.
관리자 목록의 1건은 원주소 1곳이지 사업자 수가 아닙니다. 미등록 주소는 목록에 나오지 않습니다.

저장/삭제 후 집계가 실패하면 원본 변경 결과는 유지하고 동기화 대기 주소를 표시합니다.
이어 읽기 동기화·기존 사진 가져오기·전체 재대조로 복구합니다. 완료 전에는 부분 집계를 명시합니다.
집계는 인증 근거가 아니며 삭제/조회 때 실제 파일을 다시 확인합니다. 갤러리는 24장씩 필요할 때만 조회합니다.

- 최대 42,401주소 × 2장 × 200KB = 약 17GB이며 메타데이터와 기존 개인 파일/휴지통은 별도입니다.
- 계정 전체 사용량 min(24GB, 실제 할당량−1GB)에서 저장을 중단합니다.
- 하루 저장 시도 1,000회·사진 조회 2,000회·삭제 2,000회·전체 외부 요청 10,000회 보수적 안전 상한.
  집계 작업도 요청을 사용하며 실제 Google/MYBOX 서비스 한도가 먼저 적용될 수 있습니다.
- 모든 RPC는 전역 잠금으로 직렬 처리합니다. BUSY만 제한적으로 1.5·3·5·8초(+무작위 지연) 재시도합니다.
- 카드 등록·유료 업그레이드·자동 결제 경로는 만들지 않습니다. 제한 시 오류로 중단합니다.
- **익명 공개 업로드는 장난 등록·2칸 선점·무료 호출량 소진·서비스 거부에 취약합니다.**
  삭제키는 소유권 보호 수단이지 스팸 방지/본인 인증이 아닙니다. 현재 강한 봇 방지·IP별 차단은 없습니다.
  공개 홍보 전 소규모 운영을 권장하며 동시 사용자 수·무중단·처리량을 보장하지 않습니다.
