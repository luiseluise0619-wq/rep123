# MYBOX 직접 사진 전송: 배포 전 확인

현재 운영 사진 경로는 Google Apps Script입니다. `photo-config.js`의 `directEnabled`가 `false`이고, 서버의 `PHOTO_DIRECT_ENABLED`도 `true`가 아니면 새 API는 닫힙니다. 두 스위치를 모두 켜기 전에는 기존 경로가 유지됩니다.

## 전송 흐름

1. 브라우저는 원주소·사진 해시·크기·촬영 허가를 `/api/photo-direct`에 보냅니다. MYBOX 개인 액세스 토큰은 Vercel 서버 환경변수에만 둡니다.
2. 서버는 MYBOX에 주소별 격리된 임시 폴더를 만들고 사진 한 장에 대한 일회용 업로드 URL을 발급받아 브라우저에 반환합니다. 이 URL은 사이트 주소가 아닙니다.
3. 브라우저가 압축된 JPEG를 MYBOX 임시 폴더로 직접 전송합니다. 서버는 임시 파일을 다시 읽어 크기·JPEG 구조·해시를 확인합니다.
4. 주소별 잠금을 잡고 최대 2장인지 다시 확인한 뒤, 확인된 사진만 원주소의 정식 폴더로 옮깁니다. 저장이 확인되어야 성공으로 표시합니다.
5. 관리자 목록은 정식 사진을 바탕으로 갱신하며, 갱신에 실패한 주소는 별도 대기 표시를 남겨 복구합니다. 등록 기기의 삭제키 또는 관리자 암호만 삭제를 허용합니다. 삭제는 MYBOX 휴지통 이동입니다.

## 운영 전 필수 점검

- Vercel Production 환경변수 `MYBOX_TOKEN`이 유효해야 합니다. `PHOTO_ADMIN_PASSWORD`는 별도의 강한 관리자 암호(12자 이상)로 소유자가 직접 입력합니다. 두 값은 Git이나 채팅에 기록하지 않습니다.
- MYBOX의 같은 이름 폴더 동시 생성이 실제로 한 요청만 성공하고 다른 요청에 409를 반환하는지 격리된 점검 폴더에서 확인해야 합니다. 현재 자동화 테스트는 이 동작을 모의 처리합니다.
- 별도 점검 사진으로 일회용 URL의 브라우저 CORS, 업로드→검증→정식 폴더 이동, 중간 실패 복구, 관리자 목록 갱신을 실제 MYBOX에서 확인해야 합니다. 방문 실적 주소에는 테스트 사진을 넣지 않습니다.
- 기존 관리자 목록과 새 관리자 목록의 주소 수·사진 수가 같은지 확인해야 합니다. 새 관리자 화면은 `/photo-admin`입니다.
- 위 확인 전에는 두 스위치를 켜지 않습니다. 기존 Apps Script 배포와 사진 파일은 제거하지 않습니다.

로컬 회귀시험: 저장소 루트에서 `node --test tests/*.test.cjs`. 모의 MYBOX 직접 전송 시험은 `tests/photo-direct.test.cjs`, API 안전 스위치는 `tests/photo-direct-gate.test.cjs`에 있습니다. 이 시험만으로 실제 MYBOX 운영 적합성이 증명되는 것은 아닙니다.
