# 현장 사진: Vercel → MYBOX

지도·사진·관리자 화면은 Vercel의 `/api/photo-direct`만 사용합니다. 사진 파일은 브라우저가 MYBOX의 일회용 업로드 URL로 전송하고, Vercel 서버는 저장 여부와 원주소를 검증합니다. 공개 페이지에는 MYBOX 토큰과 관리자 암호를 넣지 않습니다.

Vercel Production 환경변수: `MYBOX_TOKEN`, `PHOTO_ADMIN_PASSWORD`(8자 이상), `PHOTO_DIRECT_ENABLED=true`. 값을 바꾸면 Production 재배포가 필요합니다. 실험용 `MYBOX_DIRECT_PROBE_KEY`는 점검 페이지에만 사용됩니다.

저장 가능량은 MYBOX 계정의 실제 `quotaBytes`에서 1GB를 남긴 값으로 계산합니다. 별도의 24GB 상한은 없습니다. 계정의 다른 파일과 사진 목록도 `usedBytes`에 포함되며, 잔여 공간이 부족하면 새 사진 등록을 막습니다.

1. 사진 촬영 후 브라우저가 원주소·사진 해시·크기·촬영 허가를 서버에 보냅니다.
2. 서버가 MYBOX의 격리된 임시 폴더와 일회용 업로드 URL을 준비합니다.
3. 브라우저가 JPEG를 MYBOX로 직접 보내고, 서버가 파일을 다시 읽어 크기·JPEG 구조·해시를 검증합니다.
4. 서버가 주소별 잠금과 사진 2장 제한을 재확인한 후 정식 폴더로 옮깁니다.
5. 사진 목록을 갱신하고, 등록한 브라우저의 삭제키 또는 관리자 암호로만 삭제를 허용합니다. 삭제는 MYBOX 휴지통 이동입니다.

같은 주소에 동시 등록하면 한 요청은 `BUSY`가 될 수 있습니다. 서로 다른 주소도 사진 목록 갱신은 직렬화되므로 MYBOX 요청 제한(429), 잠금 대기, Vercel 실행 한도에 영향을 받습니다. 대기열이나 30건 동시 성공 보장은 없습니다. 저장 성공 후 목록 갱신이 실패하면 관리자 화면에서 반영 대기 항목을 복구할 수 있습니다.

이전에 배포된 외부 웹앱 URL은 저장소 변경만으로 중지되지 않습니다. 기존 링크에서 신규 업로드를 막으려면 해당 외부 배포를 별도로 사용 중지해야 합니다. 새 지도와 사진 페이지는 그 URL을 호출하지 않습니다.

검증: `node --test tests/*.test.cjs`. 연결점검은 현장 실적이 아닌 별도 MYBOX 폴더에서 수행하고 완료 후 휴지통으로 이동합니다.
