# Vercel 배포용 웹 지도 (구 · 동 · 주소 드릴다운)

`시도 → 구 → 동 → 주소`를 눌러가며 좌르륵 볼 수 있고, 주소를 누르면 지도가 이동하며
전화·사업자번호와 **구글 길안내** 버튼이 뜹니다.

> **API 키·카드 불필요.** 배경 지도는 키가 필요 없는 구글 지도 타일을 쓰고,
> 지도 라이브러리(Leaflet)는 `lib/`에 동봉되어 있어 **그냥 올리면 바로 작동**합니다.

## 구성 파일

| 파일 | 설명 |
|------|------|
| `index.html` | 드릴다운 UI + 지도 + 클러스터 + GPS |
| `addresses.js` | 주소 트리 데이터 (`웹데이터_생성.py`로 생성) |
| `lib/` | Leaflet · MarkerCluster (동봉, CDN·키 불필요) |
| `vercel.json` | 정적 배포 설정 |

## 지도 화면 (2026-10-16)

- 사진 화면과 같은 흰색·회색·파란색 구성입니다. `map-ui.css`에서 지도 UI를 관리합니다.
- 보조 기능(같은 주소·위치 확인·집계 기준·사진 관리)은 상단 ‘더보기’에 있습니다.
- 휴대폰은 아래 목록, 900px 이상 화면은 왼쪽 목록을 사용합니다. ‘목록 접기/열기’는 키보드로도 작동합니다.
- 주소 버튼은 지도 위치를 열고, 별도 ‘사진 등록·보기’ 링크는 원주소를 그대로 촬영 화면에 전달합니다.
- 파란 점은 기존 정밀 좌표, 주황 점은 근사 좌표입니다. 기존 좌표의 정확도를 새로 검증했다는 뜻은 아닙니다.
- Google 지도 타일·저작권 표시는 유지합니다. 원주소·좌표·사업자수·분류 데이터는 UI 변경으로 수정하지 않습니다.

로컬 확인: `node scripts/preview-map-server.cjs` → `http://127.0.0.1:8766`.
자동 점검: `node --test tests/map-ui.test.cjs tests/address-data.test.cjs tests/address-search.test.cjs`.

## 데이터 갱신 (주소가 바뀌면)

### 최종 한글 기준 데이터 (2026-10-15)

현재 데이터는 최종 한글 파일 `찾아가는_현장홍보_사용자분류반영_미확정3건_10pt.hwp`와
그 저장본의 HWPML 표를 대조했습니다. 전국 원주소 42,401건·사업자 44,075개는 유지합니다.
한글 대상 11개 지역은 사업자 36,452개, 데이터가 있는 시군구 199개이며,
서울·경기·인천·부산·대구·대전·청주의 행정 읍면동은 1,661개 집계 그룹입니다.
미확정 3개는 시군구·지역 합계에 포함하고 `행정동 미확정`에 표시합니다.
그 밖의 지역은 기존 주소 분류이며 한글 기준 행정동 검증 완료로 표시하지 않습니다.

사이트의 지역·동 숫자는 주소 행 수가 아닌 **사업자수의 합계**입니다.
원주소와 기존 좌표는 그대로 두고 집계용 관할만 바꿨습니다.
원주소 영등포구 534개와 현행 관할 영등포구 536개는 범위가 다릅니다.
원주소 영등포구 중 533개에 타 구 원주소 3개가 들어오고, 1개는 동작구 신대방1동에 배정됐습니다.
22개 분류는 사용자가 제공한 결정이며 독립 검증 완료를 뜻하지 않습니다.

아래 갱신 명령은 저장소 루트에서 실행합니다. 검토 원자료에는 불필요한 상세 검토 이력이
있으므로 저장소에 올리지 않고 로컬 경로로 지정합니다. HWP가 바뀌면 먼저 재수출·검산해야 하며,
현재 스크립트는 확인된 HWP 지문이 다르면 덮어쓰지 않습니다.

```powershell
python scripts/update-addresses-from-hwp.py --audit ../work/user25_applied_audit.json --hwp-xml ../work/hwp_user3_10pt_saved.xml --hwp ../outputs/찾아가는_현장홍보_사용자분류반영_미확정3건_10pt.hwp
node --test tests/address-data.test.cjs
```

검산 결과는 `data-validation.json`, 화면 집계 기준은 `data-meta.js`에 있습니다.
사진 기능 코드는 `../photo-backend/`에 있습니다. MYBOX 인증키·팀 암호는 공개 저장소가 아니라
Apps Script의 스크립트 속성에만 소유자가 직접 등록합니다. 연결·배포 절차와 무료 안전 한도는
`../photo-backend/README.md`를 참고하세요. `photo-config.js`에는 공개 `/exec` 주소만 넣습니다.
빈 값이면 지도는 사진 연결 준비 중으로 표시하며 업로드로 이동하지 않습니다.
카드 등록이나 유료 서비스 활성화를 자동으로 수행하는 코드는 없습니다.

## 좌표 추가 대조 (2026-10-16)

`coordinate-review.html`에서 원래 검토한 145곳과 이번에 재검색한 35곳을 구분합니다.
이번 35곳은 같은 대표 번지가 보였던 15곳과 상세 확인을 못 했던 20곳입니다.
건물·지번 위치 5곳을 확정하고, 실리콘앨리 2곳은 단지 대표점만 반영했습니다.
나머지 28곳과 단지 대표점 2곳의 경고는 유지합니다. 기존 대조 완료 17곳을 합해
대조 완료는 22곳, 확인 필요는 123곳입니다. 전국 모든 주소를 검증했다는 뜻은 아닙니다.

근거와 수동 판정은 `../data/coordinate-followup-20261016.json`에 있습니다.
카카오 장소 상세의 ‘지도’ 버튼이 연 **실제 장소 URL의 urlX/urlY**를 사용했으며,
일반 검색 화면의 지도 중심·화면 픽셀·인근 번지는 좌표로 사용하지 않았습니다.
WCONGNAMUL을 EPSG:5181 및 WGS84로 변환하고 공식 예제와 pyproj 결과로 대조했습니다.
하동 122-8은 정확히 일치하는 지번 결과의 전체 Plus Code를 사용했습니다.
층·호수의 실제 위치나 현장 방문 사실은 검증 범위가 아닙니다.

```powershell
node scripts/apply-map-coordinate-followup.cjs
node --test tests/coordinate-review.test.cjs tests/map-ui.test.cjs tests/address-data.test.cjs
```

원주소 문자열·사업자수·행정동 집계·사진 등록 주소 키는 변경하지 않았습니다.
이전 좌표 생성기를 다시 실행하면 이번 수정이 덮일 수 있으므로 검토 내역을 함께 보존해야 합니다.

## Vercel 배포

**방법 A — 대시보드**
1. GitHub 저장소를 Vercel에 **Import**
2. **Root Directory** 를 `web` 으로 지정 ← 이거 안 하면 화면이 안 떠요
3. Framework Preset: **Other** (빌드 명령 없음, 정적)
4. **Deploy** → 끝

**방법 B — CLI**
```bash
npm i -g vercel
cd web
vercel --prod
```

## 안 될 때 체크리스트

- [ ] **Root Directory 를 `web` 으로** 지정했나? (가장 흔한 원인 — 저장소 루트로 배포하면 index.html을 못 찾음)
- [ ] `web/addresses.js` 가 커밋되어 올라갔나?
- [ ] 지도는 뜨는데 배경(지도 그림)만 안 보이면 → 인터넷/타일 접속 문제(구글 타일). 잠시 후 재시도.
- [ ] 주소 점이 근사 위치면 → `실주소_지오코딩.py` 먼저 실행 후 `웹데이터_생성.py` 재실행.

## MYBOX 브라우저 직접 업로드 점검

`/direct-upload-probe`는 실사용 사진 화면과 분리된 진단용 화면입니다. 실제 방문 주소·사진 수·관리자 목록을 변경하지 않습니다. 점검 이미지는 MYBOX의 `연결점검_현장방문아님` 폴더에만 생성하고, 확인 후 휴지통으로 이동합니다.

Vercel 프로젝트의 서버 환경변수에 `MYBOX_TOKEN`과 별도의 임의 12자 이상 `MYBOX_DIRECT_PROBE_KEY`를 설정해야만 진단 API가 열립니다. 두 값은 사이트 코드나 대화에 넣지 않습니다. 점검 후에는 환경변수를 제거하면 API가 다시 닫힙니다. 브라우저에서 받은 1회용 URL로 직접 전송이 가능한지와 CORS 결과를 확인하기 전에는 실제 사진 업로드 경로를 바꾸지 않습니다.
