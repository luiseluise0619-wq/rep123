원본 데이터 정리

문제: 받은 엑셀은 사람이 보기 좋은 피벗(요약) 표였어요. 지역이 접혀 있고, 주소가 A열이 아니라 E열에 있고, 소계·총합계 같은 “주소 아닌 줄”이 섞여 있었죠.

쉽게 말하면 — 컴퓨터가 계산하려면 “한 줄 = 한 주소”인 깨끗한 표가 필요해요. 사람용으로 꾸며진 표를 프로그램용으로 펴는(정규화) 작업이 1단계예요.
  • 주소는 E열에서만 꺼내고, 소계·총합계 줄은 건너뜀
  • 한 주소에 사업장이 여러 개면 그 개수(사업장 수)도 같이 챙김
  • 결과를 A열 = 주소, C열 = 사업장수인 표준 엑셀로 다시 저장
# 원본_정규화.py — 핵심만
for i, row in enumerate(rows):
    if i < 3: continue          # 머리말 3줄 건너뛰기
    addr = row[4]                 # E열 = 주소
    if not addr: continue         # 소계/총합계 = 주소 없음 → 스킵
    out.append([addr, None, row[5]])   # A=주소, C=사업장수

이렇게 26,000 → 42,401건으로 늘어난 이유도 여기 있어요. 처음엔 지역이 접혀 있어서 26,000건만 보였고, 원본에서 전부 펼친 뒤 42,401건이 나온 겁니다. (합계 44,075는 “사업장 수”까지 더한 값)

2

주소를 시도 · 구 · 동으로 쪼개기

“서울특별시 강남구 역삼동 …” 한 덩어리를 시도 / 구군 / 동네로 나눠야 지역별로 묶고 지도에 표시할 수 있어요. 여기서 정규표현식을 씁니다.

개념 쏙

정규표현식(Regex)이 뭐예요?

“이런 패턴의 글자를 찾아줘”라고 컴퓨터에 알려주는 규칙이에요. 예를 들어 “한글로 시작해서 동/로/길/리/읍/면으로 끝나는 단어”를 한 줄로 표현할 수 있죠.

# 동네 = 한글로 시작하고 동·로·길·리·읍·면·가 로 끝나는 토큰
DONG = re.compile(r'^[가-힣][가-힣0-9]*(동|로|길|리|읍|면|가)$')

# 괄호 안 법정동을 최우선: "…19, 1층(호암동)" → 호암동
PAREN = re.compile(r'\(\s*([가-힣][가-힣0-9]*(동|로|길|리|읍|면|가))')

주소를 한 줄씩 어떻게 쪼개나

classify_address() 함수가 주소를 공백으로 나눈 뒤 앞에서부터 훑어요.

  • 시도 — 첫 단어가 서울특별시·경기도… 목록(18종)에 있으면 시도로 확정.
  • 구·군 — 그 뒤로 ○○시 / ○○군 / ○○구 형태를 최대 2개까지 (예: 수원시 팔달구).
  • 동네 — ①괄호 안 법정동을 최우선(…19(호암동) → 호암동), 없으면 ②본문에서 한글로 시작하는 동·로·길·리·읍·면·가 토큰.
  • 상세주소 — 구·군 뒤에 남은 나머지 전부(층·호·건물명).
왜 괄호를 우선하나? — 도로명주소는 끝 괄호에 진짜 법정동((역삼동))이 들어있는 경우가 많아서, 그걸 먼저 잡으면 훨씬 정확해요.
함정 하나

‘가’로 끝나는 이름이 동네로 잘못 잡힘

법정동 북문로3가를 잡으려고 접미사에 가를 넣었더니, 상가·아파트 이름의 ‘가’까지 걸렸어요.

예: 강화읍 중앙로 43, 141호(터미날상가) → 코드는 터미날상가를 동네로 오인.

이런 43건은 자동으로 못 거른 부분이라, 업로드한 엑셀의 동네 칸을 직접 실제 읍·면(강화읍·범서읍…)으로 바로잡았어요. 자동 분류 + 손수정 43건을 합쳐 최종 완성됩니다.

숫자가 섞인 이름(나성북1로)이나 가로 끝나는 법정동(북문로3가)까지 잡아서, 거의 모든 주소가 자동 분류돼요. 시도조차 못 찾는 것(예: #REF! 같은 오류)만 ‘기타’로 따로 모읍니다.

시도 18종 구·군 288종 동 4,401종 정상 42,401 기타 0 손수정 43

지역별로 엑셀 시트 나누기

분류가 끝나면 시도별로 시트를 쪼갠 엑셀 한 파일(지역별_주소_분류.xlsx)을 만들어요. 서울 시트, 경기 시트… 이렇게요.

ABCDEFG
원본주소시도구군동네상세주소분류상태사업장수
왜 시트를 나눠요? — 4만 줄이 한 시트에 있으면 찾기 힘들어요. 지역별로 나누면 “경기도만 보기”가 클릭 한 번이에요. openpyxl이라는 파이썬 도구로 시트를 자동 생성합니다.

참고로 전화번호·사업자번호는 개인정보라 결과물에서 뺐어요. 공개 웹에 올라가면 노출되니까요.

4

주소 → 좌표 (지오코딩)

지도에 점을 찍으려면 주소를 위도·경도 숫자로 바꿔야 해요. 이걸 지오코딩이라고 합니다. 이 단계가 이 프로젝트에서 제일 까다로웠어요.

개념 쏙

지오코딩 · 좌표계

지오코딩 = “서울 강남구 …” 같은 글자 주소를 (위도 37.49, 경도 127.03) 숫자로 바꾸는 것.

좌표계는 지구를 숫자로 나타내는 방식이에요. 지도(구글/Leaflet)는 WGS84(우리가 아는 위경도)를 써요. 어떤 데이터는 한국 전용 좌표(EPSG:5179)라 pyproj로 변환이 필요하기도 해요.

두 가지 방식을 섞었어요

방식정확도비용/조건
행정동 중심좌표 (오프라인)동 단위무료·즉시, 인터넷 불필요
카카오/VWorld API건물 단위무료 키 필요, 인터넷으로 조회

기본 지도는 동 단위 근사(파일에 미리 넣어둠)로 바로 뜨고, 정확한 위치가 필요하면 API로 실제 좌표를 받아 덮어써요. 지도 범례에 파란 점=정확 / 주황 점=근사로 구분해서 눈으로 확인돼요.

개념 쏙

왜 API가 자꾸 실패했을까? (캐시 · 재시도)

4만 건을 한 번에 너무 빨리 보내면 서버가 “너무 많아!” 하고 연결을 끊어요(RemoteDisconnected). 그래서 동시 처리 개수를 낮추고, 실패하면 잠깐 쉬었다 다시(재시도) 보내게 했어요.

또 성공한 좌표는 캐시(geocode_cache.json)에 저장해요. 그래서 중간에 멈춰도 이어서 되고, 실패한 것만 골라 다시 채울 수 있어요.

# 실패는 근사좌표로 자동 폴백 → 지도가 비지 않음
if 실좌표: 점 = 실좌표          # 파란 점(정확)
else:    점 = 동_중심좌표 + 살짝흔들기  # 주황 점(근사)

지도 만들기

좌표가 준비되면 지도에 점을 찍어요. 여기서 쓴 핵심 기술 네 가지예요.

① 마커 클러스터 — 4만 개도 안 튕기게

점 4만 개를 그대로 그리면 폰이 느려져요. 가까운 점들을 동그라미 하나로 묶어 보여주고, 확대하면 펼쳐지는 클러스터를 씁니다.

② 배경지도 — API 키 없이

키가 필요 없는 구글 지도 타일을 배경으로 깔고, 지도 라이브러리(Leaflet)는 파일에 동봉해서 인터넷 없이도 화면이 떠요(타일 이미지만 인터넷 필요).

③ 🎯 내 위치 · 🚗 길안내

  • 🎯 버튼 → 브라우저 GPS로 내 현재 위치에 빨간 점 (서버 필요 없음)
  • 점을 누르면 → 구글지도 열기 / 길안내 버튼. 실제 주소로 연결돼 정확해요

④ 구 → 동 → 주소 드릴다운

웹 버전은 구를 누르면 그 구의 동 목록, 동을 누르면 주소 목록이 나오고, 지도엔 그 지역 점만 남아요. 큰 데이터를 뒤지기 쉽게 만든 UI예요.

6

Vercel에 올리기

만든 웹을 인터넷에 공개하는 단계. Vercel은 폴더만 올리면 주소(URL)를 주는 무료 배포 서비스예요.

개념 쏙

정적 사이트 · 서버리스

우리 앱은 계산을 전부 브라우저가 해요. Vercel은 파일만 “배달”하면 되니(=정적 사이트), 서버를 관리할 필요가 없어요. 이런 방식을 서버리스라고 해요.

그래서 동시 접속 수천 명도 거뜬하고(파일 배달만 하니까), 무료 한도는 월 전송량 100GB 정도예요.

배포 팁 하나: Vercel에서 Root Directory를 web으로 지정해야 지도가 떠요. (안 하면 빈 화면)

실패한 것만 다시 채우기
